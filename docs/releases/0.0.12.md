# Simple Snip v0.0.12

- 贴图编辑失去焦点时保存当前标注并收起工具栏，不抢回其他应用焦点；在贴图、标注工具栏和右键菜单之间切换不误结束编辑。
- OCR 支持在单词内按字符拖选，经过字间空白或行边缘时继续选择；复用识别结果，避免鼠标移动时复制整个结果或绘制无效透明色块。Ctrl/Cmd+C 复制实际选区。
- 形状、折线和文字提交后保留即时预览，直到对应后台渲染就绪；丢弃过期渲染结果，避免标注短暂消失。文字使用实际字形测量宽度，蓝框与实际插入光标布局对齐，输入和等待合成的文字使用一致字体。
- 长截图改用边缘特征及多分辨率搜索，减少白底文字、固定边缘与非整步滚动造成的误匹配；保留已拼接重叠区域。完成前补采末帧，尚未拼接到新内容时保留控制栏并提示继续滚动，不直接输出普通截图。重复周期或空白内容仍拒绝不可靠匹配。
- GIF 录制中即使帧率输入框仍有焦点，暂停 / 停止数字键也可用；按键长按不再反复切换暂停状态，输入帧率时不会误触操作。
- 右键贴图菜单支持单张边框、阴影开关及原生另存为，显示效果不写入图片；菜单使用独立窗口，小贴图也不会裁切。
- 历史文件中的 GIF 现在动态贴图播放，支持多张同时显示；隐藏时暂停解码，关闭释放资源。右键另存为保留原 GIF，空格标注、旋转或翻转固定当前帧进行静态操作，原 GIF 文件保留。
- 清理贴图、编辑器、GIF 预览的旧纹理缓存；静态显示纹理按实际窗口尺寸后台生成，保留完整原图供复制 / 导出。GIF 采用容量为 1 的逐帧解码队列，不预先加载全部帧。

Windows Release 真实桌面压测：50 张独立 1920×1080 图、10 个 640×360 动态 GIF，两轮创建 / 播放 / 关闭。对比本轮未优化的动态贴图基线，私有内存峰值 4833.0 → 947.4 MiB（降低 80.4%），关闭后约 119 MiB；混合阶段 CPU 约 5%。50 张批量打开平均增加约 0.44 秒，这是纹理准备的取舍。完整协议、基线说明、复现脚本和限制见 [性能报告](https://github.com/junyi-deep/simple-snip/blob/v0.0.12/docs/PERFORMANCE.md)。该对比不等于公开 v0.0.11 安装包之间的对比。
