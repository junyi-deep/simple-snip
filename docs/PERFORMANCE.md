# Windows 贴图性能实测（2026-11-01）

本次在真实 Windows 桌面、Release 构建中打开独立贴图窗口。每个版本连续执行两轮；两轮均输出 `PERF PASS`，最后的 Release 原生截图 / 编辑 / 窗口生命周期探测也输出 `SMOKE PASS`。

## 环境与负载

- Intel Core i7-10510U，8 个逻辑处理器，约 16 GiB 内存。
- 50 张独立的 1920×1080 RGBA 测试截图，包含文字行、渐变和不同内容；原图缓冲区不共享。
- 10 个不同的 640×360 GIF，各 30 帧、70ms 帧间隔，循环播放。每个 GIF 使用独立的原生贴图窗口和有界解码队列。
- 静态图以网格缩略显示；加入 GIF 后形成 60 个同时存在的窗口。随后关闭 50 张静态图，只保留 10 个播放中的 GIF，最后全部关闭。每轮静态 / 混合 / GIF / 关闭阶段分别等待 8 / 10 / 8 / 8 秒。
- 每 250ms 采样进程工作集、私有提交内存、CPU、线程和句柄；CPU 百分比按 8 个逻辑处理器归一化。主线程另运行 100ms 心跳探针。
- 测试模式使用独立实例锁，不注册热键，不读取剪贴板，不加载 / 保存用户偏好。素材为程序生成，不采集用户桌面内容；测量时没有并行编译。

“基线”是本轮已接入动态 GIF 贴图、尚未应用纹理管理优化的 Release 源码快照，**不是公开 v0.0.11 安装包**：v0.0.11 导入 GIF 只显示首帧。基线源快照、三个版本的实际 EXE、机器信息、哈希与原始日志保留在本机 `docs/verification/`，不上传机器原始日志。

## 结果

下表为两轮稳定采样窗口的均值，内存单位 MiB。`closed` 只采样关闭后第 2–6 秒，避免把下一轮创建窗口的开销算入回收结果。混合和 GIF 基线的内存在持续增长，均值不代表稳定上限。

| 场景 | 基线私有内存 | 最终私有内存 | 基线工作集 | 最终工作集 | 基线 CPU | 最终 CPU |
|---|---:|---:|---:|---:|---:|---:|
| 50 张静态图 | 1356.0 | 766.1 | 1346.0 | 786.0 | 0.78% | 0.85% |
| 50 张静态图 + 10 个 GIF | 2848.1 | 922.3 | 2824.8 | 946.6 | 5.49% | 5.06% |
| 仅保留 10 个 GIF | 3943.3 | 430.5 | 3942.5 | 464.5 | 5.97% | 5.81% |
| 全部关闭 | 4789.1 | 119.0 | 4801.7 | 154.8 | 0.07% | 0.05% |

全过程私有内存峰值从 **4833.0 MiB 降至 947.4 MiB，降低 80.4%**。最终关闭后的两轮私有内存均值分别为 124.5 / 113.5 MiB，接近测试开始时的 108.7 MiB。基线混合播放阶段每秒增长约 256 MiB；最终两轮该阶段均没有持续增长（采样斜率约 -4 / -5 MiB/s，来自先前资源逐步回收）。基线虽然关闭后仍保留大量提交内存，但下一轮创建时会回收一部分，不能将其直接等同于永久不可回收的系统堆泄漏。

50 张批量打开耗时：基线两轮 3260 / 3785ms，最终 3953 / 3963ms，平均增加约 **0.44 秒 / 50 张（12.4%）**。其中每次测量均包含测试程序主动等待的 50×40ms；这不是单张截图延迟。内存优化仍有纹理准备成本，本次没有宣称所有指标都更快。

第一版优化曾把峰值降至 936.3 MiB，但对每个小 GIF 帧做高质量软件缩放，使 GIF 阶段 CPU 上升至约 11–13%，50 张打开约 5.5 秒。最终改为小 GIF 交给 GPU 缩放、初次显示使用廉价预览后后台生成清晰纹理，消除了这部分明显回退。最终 GIF CPU 为 5.5–6.1%，总体与基线接近。

稳定阶段主线程心跳延迟 p95 约 11–14ms，与基线相近；该探针包含 Windows 定时器误差，**不能当作输入延迟或 GPU 实际呈现帧率**。本次没有测录制 15/30 FPS 的达标率，也没有独立测量显存，工作集 / 私有提交内存不能直接视为显存数字。10 个 GIF 阶段紧接静态图关闭，仍包含驱动等资源逐步回收，不等于冷启动只打开 10 个 GIF 的最低占用。

## 原因与修改

1. 旧帧只替换 `RenderImage`，没有移除图形图集中的旧纹理。动态播放及连续标注渲染会不断产生新的图像 id；现在替换后通过窗口的 `drop_image` 回收旧图集资源，贴图、编辑器和原选区 GIF 预览均覆盖。
2. 静态贴图保留完整原图供复制 / 导出，显示纹理按窗口的物理像素大小在后台生成，缩放后重新细化；初次显示使用便宜的小预览，避免反复同步生成大尺寸 BGRA。原图不降采样、不改变导出尺寸。50 张 1080p RGBA 原图自身约 395.5 MiB，仍有不可消除的原图成本；独立原生窗口及驱动也有固定开销。
3. GIF 逐帧解码，队列容量为 1，不将整个动画读入内存。普通尺寸帧由 GPU 缩放，大帧才后台缩小；隐藏暂停解码，关闭会关闭队列并唤醒阻塞线程。暂停状态下关闭也有临时文件释放测试。

## 复现

```powershell
cargo build --release --locked
./scripts/perf-windows.ps1 -Label local
py -3 scripts/analyze-perf.py local
```

原始输出位于 `docs/verification/perf-local/`；分析 JSON 位于 `docs/verification/perf-comparison.json`。采样脚本只管理本次启动的测试 PID，默认私有内存超过 6 GiB 或运行超过 6 分钟时停止该测试实例并保存已有采样。`--perf-test` 会自动创建测试窗口，完成后关闭并退出。

本次最终本机 Release SHA256：`b5e4a653481287283ba97072dfa8a3009876b4aa9f062635a05d8566cb24c288`。它用于识别本机测量程序，不是随后 CI 安装包的校验和。结果只覆盖上述素材、分辨率、机器与显示布局；真实照片、高帧率 / 大尺寸 GIF、多屏、长期运行及 macOS 资源占用需要另测。
